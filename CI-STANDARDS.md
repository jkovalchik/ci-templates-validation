# Averitt CI Standard — Lint, Test, Code Quality, Package (v1)

> **Review draft.** This repository contains the generator source, not active GitHub Actions
> workflows. The draft has not been validated. Do not enable the generated workflows as written:
> the `*-command` overrides evaluate shell strings. Replace them with paths to reviewed,
> checked-in scripts before running CI.

Proposed standard for the approved 1.1 design item:

> Implement reusable CI modules for linting, unit tests, code quality checks, and packaging.
> (1) Lint, test, code quality, and packaging modules exist as reusable workflows or composite actions.
> (2) Modules run successfully on at least one Java and one Node sample repo.
> (3) Failed lint or tests fail the pipeline with clear output.
> (4) Inputs and parameters documented in the template repo README.

The modules live in a template repository, `averittintdev/ci-templates` (generated by
`bootstrap-ci-templates.sh`). This document is the standard. The template repo README is the
reference for inputs and parameters.

## 1. What exists today (survey of `averittintdev`)

This session could only see the organisation's **8 public repositories**: four LTL samples
and four AngularJS forks, confirmed by both an org repository search and a fork-inclusive search.
Private and internal repos were not visible, because this session's GitHub access is scoped to
`jkovalchik`. Before v1 is final, someone with org access should repeat the survey (see §9).

| Repo | Stack | Build / deps | Lint | Tests | CI |
|---|---|---|---|---|---|
| ltl-tracking-api-client-sample-java | Java 11, Spring Boot 2.7.0, Lombok | Maven + wrapper 3.8.5 (`mvnw`) | none | 1 `@SpringBootTest contextLoads` | none |
| ltl-tracking-api-client-sample-nodejs | Node, Express 4.18.1 (CommonJS) | npm + `package-lock.json` | none | none (`"test": "echo \"Error: no test specified\" && exit 1"`) | none |
| ltl-tracking-api-client-sample-php | Plain PHP (no framework) | **no `composer.json`** | none | none | none |
| ltl-tracking-api-client-sample-python | Python (`server.py` + `config.py`) | **no `requirements.txt` / `pyproject.toml`** | none | none | none |
| angular-table, angular-material-calendar, oi.select, angular-js-xlsx | Legacy AngularJS forks (2016–2017) | — | — | — | none |

What the survey shows:

* **No repo has `.github/workflows`.** We are starting from zero, so we can set one
  standard instead of reconciling several.
* No repo has lint configuration or meaningful tests, so the modules must provide
  **baseline configs**. Otherwise every adopting repo would have to write its own first.
* Two samples read keys from developer-local absolute paths (`/home/jason/...`), and the Node
  sample starts listening as soon as it is `require`d. Tests that load the app fail on a runner.
  The Java sample's only test (`contextLoads`) also fails, because `${public.key}` is not
  defined anywhere. Config must come from environment variables or test fixtures.
* The Java sample calls `String.getBytes()` without a charset. SpotBugs reports this as
  `DM_DEFAULT_ENCODING` at High confidence, so the quality stage flags it.
* Dependency manifests are uneven: Node has a lockfile, PHP and Python have no manifest at all.
  The standard therefore requires lockfiles.
* Express 4.18.1 has published high-severity advisories (body-parser, path-to-regexp). The
  dependency audit in the quality stage will flag the Node sample. That is intended.

## 2. Cross-stack principles (apply to every stack)

| # | Principle | How it is enforced |
|---|---|---|
| P1 | **Same four stages, same names, same order.** `Lint` and `Test` run in parallel. `Code quality` runs after a passing `Test`. `Package` runs only if nothing failed. | Every reusable workflow (`node-ci.yml`, `java-ci.yml`, `php-ci.yml`) has the same job graph and job names. Branch protection requires the same check names in every repo (`ci / Lint`, `ci / Test`, `ci / Code quality`, `ci / Package`). |
| P2 | **Same input names across stacks.** | `working-directory`, `runtime-version`, `run-*`, `*-command`, `junit-glob`, `coverage-file`, `coverage-threshold`, `package-path`, `artifact-name`, `retention-days`, `runs-on`, `timeout-minutes`, `dependency-review` mean the same thing in every stack. Only tool-specific knobs differ. |
| P3 | **Convention first, then baseline, then override.** | Each stage first uses the repo's own config or script (e.g. `npm run lint`, a `checkstyle.xml`, `phpcs.xml`). If there is none, it uses the template's **baseline config** and emits a `::notice`. A `*-command` input replaces either. |
| P4 | **Errors fail, warnings annotate.** | ESLint fails on errors (`max-warnings` is configurable). Checkstyle runs with `violationSeverity=error`. PHPCS runs with `ignore_warnings_on_exit=1`. SpotBugs and PHPStan findings at the configured level fail. |
| P5 | **No silent skips.** | A missing `test` script or `phpunit.xml` **fails** with an explanation. Opting out is explicit and visible in the caller (`run-tests: false`). |
| P6 | **Clear failure output, three ways.** | (a) The tool's native output in the log. (b) GitHub annotations on the offending file and line, from problem matchers, `cs2pr`, PHPStan's CI output, or test-failure annotations. (c) A Markdown step summary with test totals, failed tests and coverage. |
| P7 | **One report format per concern.** | Tests produce **JUnit XML**. Coverage is **Cobertura, JaCoCo or LCOV**. One shared summariser and one shared coverage gate serve all stacks. |
| P8 | **Reproducible installs.** | A lockfile is required (`package-lock.json`, `composer.lock`). Install uses `npm ci` / `composer install`. Maven repos should commit the wrapper (`mvnw`). The modules use it when present. |
| P9 | **Uniform artifacts.** | Packages are uploaded as `<name>-<version>-<sha7>`, where version comes from the manifest (`package.json`, `pom.xml`, `composer.json`). Default retention is 14 days. Test reports are uploaded as `<name>-test-reports`. |
| P10 | **Least privilege and safe scripting.** | Workflows declare `permissions: contents: read`. Inputs reach scripts via `env:`, never by inline `${{ }}` interpolation. Secrets are passed explicitly (`NPM_TOKEN`, `COMPOSER_AUTH`), not via `secrets: inherit`. |
| P11 | **Versioned templates.** | Semver tags (`v1.2.3`) plus a moving major tag (`v1`). Callers pin `@v1`, or a full SHA for regulated repos. Breaking input changes require `v2`. Dependabot keeps action pins current. |
| P12 | **Coverage gate is explicit.** | `coverage-threshold` defaults to `0` (report only), so legacy repos can adopt CI immediately. Every repo should set a threshold within one quarter of adoption. Target: **≥ 60% for existing services, ≥ 80% for new services**. Ratchet it up, never down. |

## 3. Per-stack standard

| Stage | Node.js | Java | PHP |
|---|---|---|---|
| **Runtime** | `runtime-version`, else `.nvmrc` / `.node-version`, else **22** (LTS) | `runtime-version`, default **21**, Temurin | `runtime-version`, default **8.4** |
| **Install** | `npm ci` (lockfile required); npm cache | Maven wrapper if present, else `mvn`; `~/.m2` cache | `composer install` (lockfile required) if `composer.json` exists; Composer cache |
| **Lint** | `npm run lint` → project ESLint config → **baseline ESLint 9** (`eslint:recommended` + Node globals) | Project-configured `maven-checkstyle-plugin` → repo `checkstyle.xml` → **baseline Checkstyle** (correctness rules only, line length 160) | `composer validate` + `php -l` on every file, **plus** `composer lint` → project `phpcs.xml` → **baseline PSR-12** |
| **Test** | `npm test` (required) | `mvn test` with JaCoCo agent | `phpunit` (config required) with `--log-junit` + `--coverage-cobertura` |
| **Test reports** | JUnit at `reports/junit/**/*.xml` (recommended) | `**/target/surefire-reports/TEST-*.xml` | `reports/junit/**/*.xml` |
| **Coverage** | LCOV `coverage/lcov.info` | JaCoCo `**/target/site/jacoco/jacoco.xml` | Cobertura `coverage/cobertura.xml` (pcov) |
| **Code quality** | `npm audit --omit=dev --audit-level=high` + coverage gate + optional `quality-command` (e.g. `tsc --noEmit`) | **SpotBugs** (threshold `High`; honours `spotbugs-exclude.xml`) + coverage gate + optional `quality-command` | `composer audit` + **PHPStan** (project config, else baseline level 1 on `src/`) + coverage gate + optional `quality-command` |
| **Package** | `npm run build --if-present` then `npm pack` → `dist/*.tgz` | `mvn package -DskipTests` → `target/*.jar`, `target/*.war` | `composer install --no-dev -o` then `tar.gz` of the app (excluding tests, VCS, reports) → `dist/` |

**Cross-stack, opt-in:** `dependency-review: true` runs GitHub's Dependency Review on pull
requests and fails on high-severity advisories. It requires the dependency graph, and
GitHub Advanced Security for private repos.

### 3.1 What an adopting repo must provide

**Node.js**
- [ ] `package-lock.json` committed.
- [ ] A `test` script. Recommended zero-dependency script for Node 22+:
  ```json
  "pretest": "node -e \"for (const d of ['reports/junit','coverage']) require('fs').mkdirSync(d,{recursive:true})\"",
  "test": "node --test --experimental-test-coverage --test-reporter=spec --test-reporter-destination=stdout --test-reporter=junit --test-reporter-destination=reports/junit/node-test.xml --test-reporter=lcov --test-reporter-destination=coverage/lcov.info"
  ```
  For Jest, use `jest --ci --coverage` with `jest-junit`. The default `coverageReporters` already writes `coverage/lcov.info`.
- [ ] Optional: a `lint` script and ESLint flat config. TypeScript repos **must** provide one, because the baseline only lints JS.
- [ ] `.nvmrc` with the Node major version.

**Java (Maven)**
- [ ] `mvnw` and `.mvn/wrapper` committed, with the executable bit set.
- [ ] `pom.xml` sets `maven.compiler.release` (or `java.version`) to match `runtime-version`.
- [ ] Optional: a `checkstyle.xml` at the root, or Checkstyle configured in the POM. Optional: `spotbugs-exclude.xml`.
- [ ] Tests must not need network or developer-local files. Use `@SpringBootTest` properties or test resources.
- [ ] Gradle is **not** supported in v1 (see §8).

**PHP**
- [ ] `composer.json` + `composer.lock` committed. Apps with no dependencies still need a
  minimal `composer.json` for autoloading.
- [ ] `phpunit.xml.dist` (PHPUnit ≥ 10) with a `<source>` element, and tests under `tests/`.
- [ ] Optional: `phpcs.xml.dist` (it must declare `<file>` entries) and `phpstan.neon.dist`.
- [ ] Code under `src/` is recommended. Baseline PHPStan analyses `src/` if it exists, otherwise the repo root.

### 3.2 Caller workflow (identical shape for every stack)

```yaml
# .github/workflows/ci.yml
name: CI
on:
  pull_request:
  push:
    branches: [main]
  workflow_dispatch:
permissions:
  contents: read
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true
jobs:
  ci:
    uses: averittintdev/ci-templates/.github/workflows/node-ci.yml@v1   # or java-ci.yml / php-ci.yml
    with:
      coverage-threshold: 60
```

Branch protection: require `ci / Lint`, `ci / Test`, `ci / Code quality`, `ci / Package`.

Private registries: pass secrets explicitly, e.g. `secrets: { NPM_TOKEN: ${{ secrets.NPM_TOKEN }} }`
(Node) or `secrets: { COMPOSER_AUTH: ${{ secrets.COMPOSER_AUTH }} }` (PHP).

## 4. Failure behaviour (acceptance criterion 3)

| Situation | Result | Where it is visible |
|---|---|---|
| ESLint / Checkstyle / PHPCS **error** | `Lint` job fails, `Package` skipped | Tool output in log, file/line annotations in PR "Files changed", job marked ❌ |
| PHP syntax error | `Lint` fails | `::error file=…,line=…` annotation per file |
| Test failure | `Test` fails, `Code quality` and `Package` skipped | Runner output, one `::error` annotation per failed test, summary table of failed tests |
| No tests defined | `Test` fails | `::error title=No test script` with how to fix or opt out |
| Coverage below threshold | `Code quality` fails | `::error title=Coverage below threshold`, summary table |
| Coverage report missing while threshold > 0 | `Code quality` fails | `::error title=Coverage missing` |
| Vulnerable dependency (≥ audit level) | `Code quality` fails | `npm audit` / `composer audit` table in log |
| SpotBugs / PHPStan finding | `Code quality` fails | Tool output and annotations |
| Missing lockfile | Setup fails in the first job | `::error title=Missing package-lock.json` / `composer.lock` |

## 5. Module layout (acceptance criterion 1)

```
ci-templates/
├── node/{setup,lint,test,quality,package}/action.yml     composite actions
├── java/{setup,lint,test,quality,package}/action.yml
├── php/{setup,lint,test,quality,package}/action.yml
├── shared/
│   ├── scripts/junit_summary.py   JUnit → summary + annotations (all stacks)
│   ├── scripts/coverage_gate.py   Cobertura/JaCoCo/LCOV → gate (all stacks)
│   ├── scripts/stage.sh           collects files for upload (all stacks)
│   ├── test-report/action.yml     shared scripts exposed as actions for custom pipelines
│   └── coverage-gate/action.yml
├── .github/workflows/
│   ├── node-ci.yml  java-ci.yml  php-ci.yml   reusable workflows (workflow_call)
│   ├── self-test.yml       runs every module against pass/broken fixtures and upstream samples
│   └── release-smoke.yml   runs the reusable workflows end-to-end on tags
├── test-fixtures/{node,java,php}/{pass,broken}/
├── test-fixtures/samples/{node,java}/   adoption changes for the LTL samples (= their PRs)
├── examples/{node,java,php}-ci.yml
└── docs/STANDARDS.md  (this document)
```

Most repos call the **reusable workflow**. Repos with unusual pipelines compose the
**composite actions** directly. Both paths run the same code.

## 6. Verification plan (acceptance criterion 2)

`self-test.yml` runs on every PR to `ci-templates`:

1. **actionlint** over all workflows.
2. For each stack, a **pass** fixture must pass lint, test, quality (coverage gate at 80%) and package.
3. For each stack, a **broken** fixture (one lint error, one failing test) **must fail** lint
   and test. The job asserts the failure, which proves criterion 3.
4. **Real sample repos (gating):** check out `ltl-tracking-api-client-sample-nodejs` and `-java`,
   apply the adoption changes in `test-fixtures/samples/<stack>/`, then run every module. All
   stages must pass: coverage gates of 70% (Node) and 50% (Java), and the package version must
   match the manifest. A passing run of both jobs is required to verify criterion 2 on real
   organization code, not just fixtures.
5. **Upstream samples as-is (informational):** run every module on the unmodified
   `ltl-tracking-api-client-sample-{java,nodejs,php}` and report each stage's outcome in the job
   summary. This shows the failure output an adopting team will see.

Predicted results for the unmodified samples, based on source review. These have not been
confirmed by a self-test run:

| Sample | Lint | Test | Quality | Package | Adoption change (in `test-fixtures/samples/`) |
|---|---|---|---|---|---|
| Java | likely ✅ (baseline is correctness-only) | ❌ `contextLoads`: `${public.key}` unresolved | ❌ SpotBugs `DM_DEFAULT_ENCODING` (High) | ✅ | Test supplies a generated key via `@DynamicPropertySource`; UTF-8 `getBytes`; null-safe `Authorization`; `final` controller; signature unit tests; `lombok.config` (`addLombokGeneratedAnnotation`) |
| Node | ❌ `no-unused-vars` (`res`) | ❌ placeholder `npm test` exits 1 (**by design, P5**) | ❌ `npm audit` high (Express 4.18.1) | ✅ | `index.js` exports its functions, starts only when run directly and takes the key from `PUBLIC_KEY_PATH`; `node:test` suite with JUnit + LCOV; Express `^4.21.2` plus a refreshed lockfile; `.nvmrc` |
| PHP | ❌ likely PSR-12 (3-space indent) | ❌ no `phpunit.xml` | — | ✅ | Add `composer.json` + PHPUnit, run `phpcbf` (not yet in v1 self-test; the PHP fixtures cover the modules) |

The **sample-java** and **sample-node** jobs are the intended acceptance checks, but neither has
run. They use the real repos plus draft adoption changes. Once those changes are merged into the
sample repos, the overlay is no longer needed.

`release-smoke.yml` calls each reusable workflow on the pass fixtures after a tag is pushed.
This verifies that the published `@v1` actions and workflows work together.

## 7. Rollout

1. Create `averittintdev/ci-templates` from the bootstrap script. Make it **public**, since it
   holds no secrets and the org already publishes samples. Alternatively make it internal and
   enable *Settings → Actions → Access → "Accessible from repositories in the organization"*.
2. Open a PR, let `self-test` pass, merge, and tag `v1.0.0` and `v1`. `release-smoke` then
   runs automatically.
3. Raise the adoption PRs in `ltl-tracking-api-client-sample-java` and `-nodejs`. Use the files in
   `test-fixtures/samples/<stack>/` plus a caller workflow from `examples/`; for Node, also commit
   the refreshed `package-lock.json`. After they merge, drop the overlay and make the upstream jobs
   gating.
4. Add the required status checks to branch protection or rulesets (§3.2).
5. Within one quarter, every active repo sets `coverage-threshold` (P12).

| pnpm / yarn | Not seen | `package-manager` input |
